## 1. 三个致命坑（都踩过、都已解决）

### 1.1 Gowin 不支持中文路径（最坑）

Gowin **1.9.10.02** 在含中文的路径下综合必挂：

```
ERROR (SP0002) : Corrupted project file: "E:/.../impl/gwsynthesis/pendulum_fpga.prj"
```

原因：Gowin 自己生成的 `impl\gwsynthesis\*.prj` 里写的是**中文路径**（UTF-8 内容），GowinSynthesis 再读时解码失败。

- 命令行同样中招（路径显示成 `E:/??/fpga?/`）；`encoding system cp936` **无效**；`subst` / `DefineDosDevice` **无效**
- **解法**：工程实体放纯 ASCII 路径（`E:\fpga_pd`），中文位置改用**目录联接**（`mklink /J`）
- GUI 能"打开"中文路径的工程（标题变 `[Design Summary]`），但**一点综合就报上面那个错**
- **打开工程一律用 `E:\fpga_pd\pendulum_fpga.gprj`**

### 1.2 led 的 C10 / T10 是 SSPI 专用脚

板载 LED 有 6 个，其中 `led[?]=C10`、`led[?]=T10` 落在 SSPI 专用引脚上，直接约束会报：

```
ERROR (PR2017) : 'led[1]' cannot be placed according to constraint, for the location is a dedicated pin (SSPI)
```

**两种走法**：
- **本工程采用**：只用另外 4 个板载 LED（`R9 / R7 / N6 / P7`），**保留外部 Flash(MSPI) 上电自启动能力**
- 想用满 6 个：加 `set_option -use_sspi_as_gpio 1`（或在 GUI 里勾 `Project → Configuration → Place & Route → Dual-Purpose Pin → Use SSPI as regular`），代价是**不能再用 Flash 配置启动**

### 1.3 逻辑派 G1 板载资源实况

- **按键只有 2 个**：`key[0]=D11`、`key[1]=F10`
- LED 6 个（`R9 C10 R7 N6 T10 P7`，低电平点亮）
- UART：`F12`(TX) / `F13`(RX)，板载 USB 串口
- 时钟：`T7`，50MHz；**没有复位键**（工程用上电计数器产生内部复位）
- 排针 `H5/H6`（网表位号，丝印可能标 J5/J6）

## 3. 与 STM32 的参数对应（逐项一致）

## 4. 本次对 STM32 `(2)` 工程的改动（已同步到 FPGA 版）

### 4.1 `Location` 改成 `int32_t`

原来 `int16_t`，4216 count/s 时 **7.8 秒就溢出**。

### 4.2 K2/K3 步进改成 60°（宏换算）

```c
#define ENCODER_CPR    408.0f
#define POS_STEP_DEG   60.0f
#define POS_STEP       (POS_STEP_DEG * ENCODER_CPR / 360.0f)   // 60度 → 68 count
```

### 4.3 K4 增加"记录初始位置"

K4（仅停止态）= 标定 `CENTER_ANGLE` + `Location=0` + `LocationPID.Target=0` + 清各误差。

### 4.4 入区（状态 1 → 4）回到"位置归零"的原版行为 ★

**这是本次最重要的一个 bug 修复。**

曾经按"起摆后回到 K4 初始位置"改过（入区不清零 `Location`），结果出现**"平衡后横杆不断加速转圈"**：

> 起摆过程中横杆被 ±35 推力带着转了好几圈 → 入区时 `LocationPID.Target − Location` 有几百~上千 count → 位置环 `Out = 0.4×误差` **立刻饱和到 ±100** → `AnglePID.Target = CENTER_ANGLE ∓ 100` 变成**固定摆杆偏置** → 电机恒定输出 → 横杆**匀加速**朝一个方向转，而且 `Location` 越转越远，位置环永远出不了饱和。

**修法（两边一致）**：入区时把位置与位置目标一起归零

- STM32：`Location = 0; LocationPID.Target = 0; Error0 = Error1 = 0;`
- FPGA：`enc_zero`（位置清零）+ `pos_target <= 0` + `pos_clr`

**FPGA 侧还顺带改了一处时序**：`pid_pos.v` 的 `clr` 原来是"`err1 <= err`"，但 `enc_zero` 要**下一拍**才把位置清零，这一拍 `err` 还是旧的大偏差 → 会变成一次微分冲击。改成 `err1 <= 32'sd0`。

**代价**：平衡后横杆停在**起摆完成时那个位置**，不再回到 K4 时的初始位置。
（要恢复"回初始位置"，做法是入区时把 `pos_target` 限制在当前位置 ±204 count（半圈）以内，别让位置环饱和。）

## 5. ModelSim 仿真环境

**位置**：`E:\fpga_pd\sim\`

| 文件 | 用途 |
|---|---|
| `run_sim.do` / `tb_top.v` | 闭环仿真（虚拟摆 + 电位器/ADC 模型 + 编码器模型） |
| `run_angle.do` / `tb_angle_map.v` | **角度环开环**：按 K1 后逐段给定摆角，看电机输出 |
| `run_states.do` / `tb_states.v` | **各状态覆盖**：0/1/21~24/31~34/4 逐个构造触发 |
| `run_gui.do` / `run_states_gui.do` | 带波形的 GUI 版 |

**仿真加速**：`clk_tick` / `adc_if` 都有 `parameter DIV`（默认 1，**综合时行为不变**），tb 里 `defparam ... DIV = 50`。
→ **1ms 物理时间 = 1000 个 50MHz 周期 = 20µs 仿真时间**，物理时间轴（1/5/40/50/100ms 节拍）比例不变。

**⚠️ 波形时间轴是"仿真时间"**：整段 6.9 秒物理的测试，波形上只有 **138ms**。
`tb_states.v` 里加了 `phys_ms` 计数器并放进波形，看它就等于看物理毫秒。**波形时间(µs) ÷ 20 = 物理时间(ms)**。

**关键跳转点**（波形时间 / 物理时间）：

| 事件 | 波形 | 物理 |
|---|---|---|
| 按 K1 起摆 | 27.2 ms | 1361 ms |
| 右极值 → 正转 | 41.4 ms | 2072 ms |
| 左极值 → 反转 | 54.2 ms | 2712 ms |
| 入区 → 状态 4 | 66.2 ms | 3312 ms |
| 电机方向翻转 | 114.2 ms | 6112 ms |

## 6. 仿真验证到的结论

### 6.1 已验证通过（RTL 侧，逐条对上 STM32）

- **采集**：12bit 数值域、16 次平均（3ms 更新、有 60µs 仿真延迟）
- **编码器**：AB 四倍频、位置累计、可清零
- **按键**：20ms 消抖、单击、长按（标定）、双击；板载 2 键映射 4 功能
- **标定**：`CENTER_ANGLE` 从初值 2010 → 实测 2008；位置零点/误差同步清零
- **状态机**：0/1/21~24/31~34/4 迁移与推力方向全部正确（详见下表）
- **角度环**：极性正确（摆往哪偏，电机往"扶回来"的方向转）、死区 ±5、限幅 ±100
- **串口**：持续发送 16 字节帧

### 6.2 各状态 → 电机输出（实测）

| 状态 | 电机指令 | IN1/IN2 |
|---|---|---|
| 0 停止 | 0 | 0/0 |
| 1 判断 | 不驱动 | — |
| 21/22 左推 | **+35** | 0/1 |
| 23/24 右推 | **−35** | 1/0 |
| 31/32 右推 | **−35** | 1/0 |
| 33/34 左推 | **+35** | 0/1 |
| 4 PID | 角度环输出 | 视符号 |

（21/23/31/33 在 FPGA 里只停 1 拍就转 22/24/32/34，功率段各持续 100ms，与 STM32 一致。）

### 6.3 状态 4：摆角 → 电机（实测）

| 摆角 | ADC | 环输出 | 电机指令 | IN1/IN2 |
|---|---|---|---|---|
| +20° | 1808 | +90 | +90 | 0/1 |
| +10° | 1908 | +60 | +60 | 0/1 |
| +5° | 1960 | +44 | +44 | 0/1 |
| +2° | 1988 | +36 | +36 | 0/1 |
| 0° | 2008 | +30 | +30 | 0/1 |
| −2° | 2028 | +5 | +5 | 0/1 |
| −5° | 2060 | −46 | −46 | 1/0 |
| −10° | 2108 | −61 | −61 | 1/0 |
| −20° | 2208 | −91 | −91 | 1/0 |

输出 = `0.3×(2008−ADC)`（P 项）+ 积分项（该测试里积分顶在 ±30 饱和，因为每段固定 400ms、误差同号）。

### 6.4 没跑通的：闭环起摆

`tb_top.v` 的闭环里，摆能被泵起来、能持续摆动，但**摆幅稳定在 30~60°，达不到入区所需的 130°**（`CENTER_RANGE=500` → 要摆到离竖直 50° 内）。扫遍 `TAU_MAX` 0.12~0.30 和摆杆阻尼 0.05~0.6 都如此。

**结论**：这是**虚拟摆模型的注能效率**问题（对照实测"3 次来回、3 秒立起"，真实系统每次摆动增幅约 40°，模型只有 10~15°），不是 RTL 的问题。**RTL 侧已全部验证过**。

**闭环仿真里修掉的 4 个模型侧坑**（都是"摆永远不动/摆幅不增"的原因）：
1. **摆角不能加 ±180° 硬限位**：每次垂到底把角速度清零＝每次把能量丢掉 → 必须**角度回绕**（`alpha > π → alpha -= 2π`）
2. **标定必须在摆竖直时做**：一开始 `hold_rod` 默认生效，标定时摆被扶在 175° → `CENTER_ANGLE` 被标成 260（不是 2008）
3. **摆静止在精确 180° + 推力上下对称 → 净冲量为零**：真实操作是"人扶着摆杆按 K1 再松手"
4. **单向耦合摆模型不够**：换成完整 Furuta 2×2 联立（含摆对臂的反作用力矩）

### 6.5 对硬件有用的两条结论

1. **摆杆必须能自由转到底**，不能被结构挡住——否则每次撞停都把能量吃掉，自动起摆永远起不来
2. **上板如果起摆费劲，优先调 `START_TIME`（推力持续时间）而不是 `START_PWM`**——问题出在"注能窗口没吃满"，不是力矩不够
