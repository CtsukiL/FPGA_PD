# 倒立摆 FPGA 项目总览（合并自 12 条会话记忆，状态截至 2026-10-06 会话收尾）

## 2. 硬件与引脚
- FPGA 逻辑派 G1，50MHz（T7）；TB6612（**STBY 需硬件拉高**）
- **角度传感器 SV01A103AEA01R00**（Murata，**已停产**）：有效电角 333.3°、开口区 ≤15°（输出不连续）、10kΩ±30%、线性度 ±2%、额定 5V（这里 3.3V 供电、比率输出）、9.90 mV/度
- **ADC 数据线** `adc_d[0..9]` = R14 T15 T13 T11 P12 P11 N10 M11 E10 D10（= H5-35/36/33/34/31/32/29/30/27/28）、`adc_otr=C9`(H5-25)、`adc_clk=C11`(H5-23)；`adc_oe`/A9 已废弃
- **OLED**：`oled_scl=J14`(H5-3)、`oled_sda=J16`(H5-4)、电源 H5-38(3.3V)/H5-39(GND)
- **编码器**：`enc_a=K16`(H5-1)、`enc_b=J15`(H5-2) —— **A/B 已在 `top.v` 例化时对调**（2026-10-03）
- **按键** H6：`key[0..3]` = N14/N16/R16/P15（= H6-36/35/34/33）：K1 启停、K2/K3 位置 ±、K4 标定
- **电机** H6：`motor_pwm=G15`(7)、`in1=G14`(8)、`in2=G16`(9)
- 其它：`led[0..3]=R9 R7 N6 P7`、`uart_tx=F12`；**`led[1]`(C10)/`led[4]`(T10) 是 SSPI 专用脚，别用**（保留 Flash 自启动）
- 量密度高的排针/芯片脚时按丝印名（IOR7B/IOT13A 这类 Gowin IO 站点名）找，**不要按「第几针」找**

### AD 板（U1=TPL740F30-5TR、U2=3PA1030、U3=TPH2501-TR）
- **H3 = 板电源 + 数字接口，H2 = 传感器接口**（H2-1=VCC 3.3V、H2-2=VIN 信号、H2-3=AGND）
- **量程 1V**（REFSENSE 与 VREF 短接），1 LSB ≈ 0.977mV
- 前端反相衰减：**本板实测 `AIN = 0.993 − 0.1×V(H2-2)`**（设计值 0.5113），即前级 +IN 偏置偏高，软件用 `OFFSET` 补偿
- ⚠ 3PA1030 芯片本体脚号与 H3 连接器脚号完全不同（芯片 D0=pin3…D9=pin12、OVR=13、CLK=15、OE=16、STBY=17、REFSENSE=18、REFTS=21、REFBS=25、VREF=26、AIN=27、AVDD=28），量芯片脚别按 H3 编号数
- **传感器信号线已直连 AD 板输入端**（跳过原线束/插头）—— 原线束是读数跳变源之一；换回线束要留意

## 3. 时钟与采样
- `sys_clk` 50MHz；`adc_clk` 5MHz（50MHz/10）
- **采样节拍必须与电机 PWM 同步**：`motor_pwm` 输出 `smp_pulse`（`pwm_cnt==PWM_PERIOD-1`），`adc_if` 2 分频 → **100us 一次**，1ms 内 10 次平均 + 4 点滑窗；除法 `(x×3277)>>15`
- 节拍：1ms（采样）、5ms（角度环）、40ms（起摆判据三点采样）、50ms（位置环），`clk_tick` 独立分频
- `adc_if`：`OFFSET=1998`、斜率 `×2.9375`；输出 `raw_code`/`avg4_out` 供屏显示
- `encoder_if`：4 倍频 + 3.6us 数字滤波；`pos_clr` 记位置零点

## 4. OLED 四行（页 0/2/4/6）

```
page0  CNT xxxx  ST xx
page2  L ±xxxx  V ±xxxx     横杆位置(count) / 横杆速度(count/s)
page4  DEG ±xxxx  POS ±xxxx 位移换算轮子转角(整数度，不回绕) / 目标位置(count)
page6  ANG xxx.x  CT xxxx
```
- `DEG` = `location * 9039 >> 10 / 10`，**故意不回绕**（按一次 K2 能看到 +360 持续累加）；旧版 `arm_v` 是回绕的，别照搬
- `V` 来自 `ctrl_fsm` 的 `bar_vel`（location 50ms 差分 ×20），静止时有 ±20 count/s 量化抖动
- `CT = center_angle>>2`；**CT=600 ↔ ANG≈195 度**
- `CNT = angle>>2`（0~4095 的 angle 尺度折算到屏上是 ÷4）
- 每行 **21 字符位**（128px/6px），改内容后数一下 ≤21；字库自绘 5x7，每字节一列、bit0 = 顶行；现有字符含数字 + `+ - . 空格 A C D E G I L M N O P R S T V W X`
- 上电第一轮刷全部 8 页清屏；帧间更新四行；页刷新轮转 page0→2→4→6→page0
- `SCL_HZ` **必须 50000**；50kHz 下一帧约 **70ms**（四行约 90ms），不是 0.4s

## 5. 按键与轨迹

| 操作 | 行为 |
|---|---|
| K1 短按 | 停止 ↔ 起摆 |
| **K2/K3 短按（<400ms）** | 目标 ±408 count（±360°），梯形速度曲线，**约 3.4s** |
| **K2/K3 长按（>=400ms）** | 手动点动，按住期间慢移，松手立即停 |
| K4 短按 | 标定平衡点（仅停止态） |

- 点动与曲线只在**状态 4（平衡）**下起作用；停止态按了会被入区清零
- 长按点动时 `pos_cmd` 与 `pos_set` 同步推进并取消未走完的行程 → 松手后目标就是当前位置
- `key_ctrl.v`：`DB_MS=20`、`HOLD_MS=400`；进入过长按态的这次按压松手时不再发 `ev_single`
- 轨迹发生器在 `ctrl_fsm.v` 内，50ms 节拍；K2/K3 只写目的地 `pos_set`，发生器产出 `pos_cmd`（`pos_target` 由 `output reg` 改 `output wire`，top.v 不用改）
  - 减速判据：剩余距离 ≤ `v(v+A)/(2A)` 才开始减速 → 到位时速度刚好归零（**零过冲**）
  - 每拍速度只变一档、限幅 `VMAX`；距目标 ≤1 档且速度 ≤1 档 → 吸附到位
  - **加速度分频**：`acc_ph` 在 `tick_50ms` 递增，`t_acc_en = (acc_ph == 4'd0)` 才允许 `traj_vel` 变一档；**减速距离公式必须跟着乘 N**：`t_dec_dist = (v*(v+1)*TRAJ_ACC_DIV) >>> 1`，否则末端突然刹停
  - **clamp 坑**：写成「vel>0 就夹到 pos_set」会让运行中反向时 `pos_cmd` 一步跳到目标；正确写法是「越界方向与 `t_diff` 符号一致时才夹」：`(t_diff>=0 && cmd_try>pos_set) || (t_diff<=0 && cmd_try<pos_set)`
  - 入区（S_JUDGE→S_PID）和 K4 标定时 `pos_set/pos_cmd/traj_vel` 一起归零
  - **验证方法（可复用）**：先用 Python 把组合逻辑逐拍重写做数值模拟（场景：0→102、0→8、102→-102、运行中反向），确认无过冲且收敛再综合上板
- 关键参数：`POS_STEP`=408、`TRAJ_VMAX`=8（160 count/s）、`TRAJ_ASTEP`=1、`TRAJ_ACC_DIV`=2（200 count/s²，加速到峰值 16 拍 = 800ms）、`JOG_STEP`=4（80 count/s）、`POS_FF`=3、`CENTER_INIT`=2400（屏上 CT 600）

## 7. 硬结论 / 红线（都上板实测过，别再试错）
1. **编码器 A/B 方向必须与电机方向匹配**（`top.v` 里 A/B 对调）。不匹配 = 位置环正反馈 = 横杆越转越快。定位法：① 临时屏蔽位置环（`ang_target <= c_s`）确认角度环无责 → ② 屏上看 `L±xxxx` 确认编码器有信号（手转就变、手不动不涨）→ ③ 翻 A/B
2. **角度环 `Kd` 不能低于 0.4**：试 0.2 → 直接失稳、一给力就加速；试 2.5（位置环 Kd）→ 机械固定后会「一到平衡点猛地一冲刹不住」
3. **电机死区不能加滞环**：试过「启动 ±6 / 停止 ±3」→ 竖直附近形成控制死区，「咔咔调整 → 猛加速 → 掉下来」；保持单阈值。**电机死区 5 → 2 是最有效的一刀**：调整步长小了、小幅度倾斜恢复快了、转一圈过冲改善很多
4. **`oled_scl` 必须 50kHz**：400kHz → I2C 失步、屏内容冻结（驱动不查 ACK，从机收不到也不报错）
5. **AD 采样必须与电机 PWM 同步**：PWM 50us / ADC 125us 比值 2.5 非整数 → 采样点相位每次漂 180° → 电机一转读数抖 ±10（拔掉电机供电立刻恢复 1~3）
6. **`motor_pwm` 的 IN1/IN2 对调是错的**：上板后起摆阶段疯狂抽搯、根本起不来（已回退）⇒ 电机原方向正确
7. **`pid_angle.v` 的 `INT_MAX` 不能砍**：3001 → 300 上板即「起摆后不断加速转圈」。机理：角度环要输出力矩就必须有误差，积分负责「无误差维持输出」；积分不够时克服摩擦所需输出 ≈5 → 稳态角度误差 ≈ 5/0.3 ≈ **17 count ≈ 1.4°**，固定倾角给横杆恒定加速度，位置环（±40）拉不回来
8. **死区档只能用「有没有轨迹/点动命令」切，不能用误差大小**：门限 6（10-04）与门限 40（10-06）各栽一次 —— 静止平衡时位置误差本身就常在几十 count 量级（巡游幅度就 40）→ 反复切小死区 → 噪声穿透 → 立不住。**档位门限必须明显高于系统稳态静差（>= 20）**
9. **静止档的输出死区会把 Kd 阻尼一起截掉**：`pid_pos` 输出死区作用在**总输出**上，`|0.4e + 2.5Δ| < 3` 时整个输出归零 → 误差小、速度小时位置环对横杆是**零阻尼**（滑行）。这一条同时解释：① 为何「加大 Kd 完全无效」② 「静止 2 s 巡游」与「轨迹走完收敛很久」同源
10. **机械从「有空程」变成「无空程」后，位置环需要的阻尼会变大**（空程以前白送机械滞后）：联轴器/顶丝拧紧后必须 KD 4.0
11. **位置环纯 PD 的固有矛盾**：「不是慢就是跳」；加**位置环积分**会引入**第二个积分器** → 相位裕度不够 → 低频摆（**长按「走一段、回移一段、反复」**）。压 `I_MAX`、加强泄漏、条件积分抗饱和都**未能根治** → 最终 **I_MAX = 0（关掉位置环积分）+ 前馈 `POS_FF`=3 供给恒定推力**（结构上只留角度环一个积分器）
12. **位置环输出是「直接偏置角度目标」**（`ang_target = c_s - pos_out_w`）：限幅 ±100 等于允许摆杆被撑到 100 count（≈12.7°）去换横杆回中，手碰一下 Kd 项就打满 → 大幅摆动。**收到 ±40（≈5°）是对的方向**
13. **位置环不要加 Ki**：过冲/来回正是积分饱和的典型成因。要修静差就**减小输出死区**，不是加 Ki
14. **给位置环输出加斜率限制是错的方向**（已实测失败）：SLEW=4 count/50ms 时 0→40 要 10 拍（500ms），等于串一阶滞后吃掉相位裕度 → 低频来回次数比不加还多。**平滑要靠轨迹发生器，不是事后限速**
15. **角度环 D 项必须脱离死区**：若 `err` 在死区内被清成 0，则 `d_err = err - err0` 在平衡点附近恒为 0 → 阻尼全无 → 扰动后要在竖直附近来回好几趟。改法：**`d_err = err_raw - err0`**（D 用原始误差，P/I 仍用带死区的 `err_p`）。噪声代价：静止读数 ±4~8 count 经 Kd 0.4 放大 ≈ ±1.6~3.2，仍在电机死区以内。（当前桌面版 `pid_angle` 无 err 死区，无此问题）
16. **轨迹运动顿挫的根因 = 位置环纯 P + 三层死区导致的粘滑（stick-slip）**：匀速物理上不需要持续力 → `pos_out` 理想值很小 → 但纯 P 无法平滑维持恒定小输出 → 链条末端又有电机死区 → 循环「攒误差（电机停）→ 推一下 → 误差回落 → 电机停」→ 周期 150~250ms。**本质 = 无积分控制 + 库仑摩擦**
17. **积分泄漏对负数不对称**：`i_cl - (i_cl >>> 6)` 里 `+32>>>6 = 0`（不衰减）、`-32>>>6 = -1`（每拍衰减）→ **K2 顺滑、K3 一直不顺滑**。改为先取绝对值做泄漏再恢复符号。教训：对带符号量做 `>>>` 再送反馈的地方都要检查正负对称性
18. **咔哒声 = 联轴器/顶丝没拧紧（反向空程）**：手推来回变向、每换一次方向响一声，声源在电机轴连接处。判别法：**横杆能动而屏上 `L` 不动的那一段就是空程**。拧紧后运动丝滑了 —— 之前记的「运动全程粘滑」有一部分就是它
19. **烧录必须 `External Flash Mode`**（见 §1）

## 12. 写码 / 环境坑
- **Verilog 加法表达式位宽 = 操作数最大位宽，会静默截断**；移位同理；赋给窄 wire 报 EX3791 → 先落 32bit 中间 wire 再 `[n:0]` 取位
- **×N 优先用移位相加**（×4.5 = `(x<<<2)+(x>>>1)`；×2.9375 = `x + (x<<<1) − (x>>>4)`；×2.5 = `(x<<<1)+(x>>>1)`），比乘法安全
- **非阻塞赋值的顺序陷阱**：`a0<=angle;` 之后同拍读到的 a0 还是旧值 → 要「先赋值再判断」必须显式写独立 wire（`n0/n1/n2`）
- **ANSI 端口已声明 `output reg` 时，模块体内不能再 `reg` 声明一遍**（EX3628）
- **`NOTE (EX0101)` 不是告警**
- **行尾必须归回文件原风格**：`ctrl_fsm`/`pid_pos`/`pid_angle`/`encoder_if`/`key_ctrl`/`motor_pwm` 是 **CRLF**；`adc_if`/`top`/`oled_ssd1306` 是 **LF**。`edit_file` 写多行会引入裸 LF，要用字节级脚本把裸 LF 补成 CRLF
- **本工程 `.v` 文件实际是 UTF-8（不是 GBK）**
- `edit_file` 改文件前必须先 `read_file` 观察，否则报 stale / FS_NOT_OBSERVED
- **PowerShell 里 `$env:TEMP` 被映射到会话临时目录** → 写临时文件用真实路径 `C:\Users\Mr.NK\AppData\Local\Temp`
- **PDF 提取用 `pypdf`**（3PA1030 手册用 pdfplumber 会卡）
- **示波器读数的坑**：曾把 50MHz 读成 5MHz、把占空比 3% 的 I2C SCL 当恒高；万用表量数字信号读到的是平均值
- **两条已知时序违例**（原件就有，非引入，靠 50kHz I2C 节拍掩盖，功能正常）：① OLED 显示链 `angle→32bit乘除→十进制拆位→glyph→tx_byte→sda_low` ≈25.6ns，`Setup TNS ≈ -6.5ns`；有效修法是 **4 级流水**并有 `×83>>10`/`×833>>10`/`×3277>>15` 替掉除法 ② `pid_pos` 输出链裕量只有 **+0.283ns**，插一级流水（锁存 `err` + 延迟一拍 `calc_en_d`）可提到 +5ns 以上。注：在 32bit 组合除法器后插寄存器**没用**（试过反而恶化到 -54ns / 16 条端点）
